\chapter*{ABSTRACT}
\addcontentsline{toc}{chapter}{ABSTRACT}
PurpleAgents is an autonomous \emph{purple-team} framework for testing and strengthening the safety of AI systems such as large language models (LLMs), chatbots, and AI agents. Traditional security work is split: attackers (red teams) test a system only now and then, defenders (blue teams) react after something goes wrong, and the lessons from each test are rarely turned into lasting protection. PurpleAgents brings attack and defense together into one continuous, self-improving cycle inside a safe, authorized environment.

The core of the framework is a \textbf{dual-reasoning engine}. For every attack, the engine reaches a conclusion in two independent ways. The first path is \textbf{evidence-first}: it looks at what actually happened --- the prompt sent and the model's response --- and decides whether the attack succeeded. The second path is \textbf{hypothesis-first}: it takes a list of known attack types and tests the evidence against each one, keeping only the explanation that fits. A conclusion is accepted only when both paths agree. This prevents the system from trusting a single wrong signal.

An offensive (red) agent sends adversarial prompts such as jailbreaks and prompt injections to the target model, while a defensive (blue) agent tries to detect and block unsafe behaviour. A reflection step then studies each missed attack, finds the exact reason it slipped through, and proposes a concrete fix such as a stronger guardrail rule. Every attack, its evidence, the reasoning path, the confidence level, and the outcome are stored in an auditable memory. The defining idea is a \textbf{closed learning loop}: a missed attack is not just a failure --- it becomes a verified lesson, so the defense improves on the next cycle. Human approval governs any high-impact change. By attacking, defending, reasoning, and learning in one loop, PurpleAgents aims to make an AI system measurably harder to break over time.
